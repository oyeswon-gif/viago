# VIAGO 실수 방지 체크리스트 (회귀 노트)

> 2026-16일까지 VIAGO를 고치면서 실제로 겪은 사고를 **같은 방식으로 다시 겪지 않기 위한 노트**입니다.
> 큰 작업을 시작하기 전과 `main`에 올리기 전에 이 문서를 먼저 읽고, 아래 `M#` 항목을 확인합니다.
> `node tools/ci/run.mjs`(GitHub Actions `VIAGO CI`)가 자동으로 막아 주는 항목에는 **CI** 표시가 있습니다.

## 쓰는 법 (5분)

1. 작업 시작 전: 이 문서의 `M1~M16`을 훑고, 이번에 건드리는 영역의 항목을 기억해 둡니다.
2. 작업 중: 같은 증상이 나오면 아래 "원인"을 먼저 읽습니다. 대부분 데이터가 아니라 **표시·캐시·타이밍** 문제입니다.
3. 올리기 전: `node tools/ci/run.mjs` → 로컬 브라우저 검사(`tests/e2e/smoke.mjs`는 CI가, 실제 배포 전에는 재원 님 기기 확인) → 배포 절차 8단계.

## M1. `<label>` 안에 자동완성 input — 선택 직후 포커스·입력값이 되돌아감

- **증상**: 장소 검색에서 추천을 눌러도 방금 고른 이름이 사라지고 포커스가 튄다.
- **원인**: `<label>`이 입력창을 감싸면 클릭이 label → input으로 두 번 전달되고, 지연 응답이 늦게 도착해 입력창을 덮어썼다(2026-11-14 레이스).
- **규칙**: ① label은 `for=`로만 연결한다(`<label><input></label>` 금지). ② 비동기 응답은 반영 직전에 `세대·입력값·여행 ID·열림 상태`를 다시 확인하고, 입력·닫기에서 `AbortController`로 취소한다.
- **자동**: CI 회귀 불변식 R6 + `viagoPlaceDetails(...signal)`/`invalidate()` 존재 확인.

## M2. 쿠키 세션에서 `idToken`이 빠져 모든 요청이 401

- **증상**: 초대를 받아도 "참여 확인 필요"로 돌아오고, 저장이 전부 실패한다. 원인을 권한 문제로 오해하기 쉽다.
- **원인**: 쿠키 기반 세션 쪽 경로가 `Authorization` 헤더에 `idToken`을 넣지 않았다(2026-11-15).
- **규칙**: Firestore REST 호출은 **한 곳(`authedFetch`)에서만** 만들고 항상 `Bearer <idToken>`을 붙인다. 401을 "멤버 아님"으로 해석하지 않는다(멤버 확인은 `members/{uid}` 존재로).
- **자동**: CI R5.

## M3. `render()`·동기화가 사용자가 맞춘 지도 카메라를 덮어씀

- **증상**: 지도를 확대하면 갑자기 세계지도까지 축소된다(2026-11-16 신고).
- **원인**: 마커를 다시 그릴 때마다 `fitBounds`를 무조건 호출했고, 늦게 도착한 맞춤이 사용자 조작을 되돌렸다.
- **규칙**: 자동 맞춤은 `viagoFrameMap` 한 곳에서만. 사용자가 만진 뒤(`viagoCameraTouch`) 같은 맥락의 자동 맞춤은 하지 않는다. 「전체 보기」·검색 결과·장소 선택처럼 **명시적 요청만** `force:true`. 여백은 지도 크기의 35%를 넘기지 않는다(넘기면 Google이 최소 배율까지 줄인다).
- **자동**: CI R1 (`drawLocated` 안에 직접 `fitBounds` 금지).

## M4. SW가 캐시 우선이라 새 배포가 옛 코드로 실행됨

- **증상**: 배포했는데 화면은 그대로. 새 화면 + 옛 `viago-auth-client.js`가 섞여 초대 참여만 실패.
- **원인**: v9까지 JS를 `cacheFirst`로 응답했다. SW `VERSION`을 안 올리거나 `?v=`가 어긋나도 같은 일이 난다.
- **규칙**: HTML·JS·CSS는 **네트워크 우선**(v10 유지), 오프라인일 때만 캐시. 코드를 고치면 **SW `VERSION`과 `index.html`의 `?v=`를 함께 올린다**. 새 워커는 `skipWaiting`+`clients.claim`, 화면은 새 버전을 안내하고 한 번 새로고침한다.
- **자동**: CI M4 검사(`VERSION`·`?v=` 일치), 자산 지문 불일치 시 실패, R2·R3.

## M5. 캐시 목록·`?v=`에 없는 파일을 참조 → 오프라인에서 깨짐

- **증상**: 오프라인에서 아이콘·스플래시가 비거나 404. `SHELL_FILES`에 없는 새 파일은 오프라인에서 안 뜬다.
- **규칙**: 새 껍데기 자산은 ① 저장소에 실제 파일 ② `service-worker.js` `SHELL_FILES` ③ `index.html`의 `?v=` 3곳을 함께 갱신.
- **자동**: CI 껍데기 검사(파일 존재·목록 포함·`?v=` 통일).

## M6. 비밀키·개인정보가 공개 저장소로

- **증상**: 서비스 계정 키·refresh token·실여행 일정이 공개 커밋에 남는다.
- **규칙**: 저장소는 **public**이다. 브라우저용 Maps 키(리퍼러 제한)만 `index.html`에 두고, 그 밖의 키·토큰·`.env`·백업 JSON은 절대 커밋하지 않는다(`.gitignore` 확인). 테스트 데이터는 합성(fixture)만 올린다.
- **자동**: CI 비밀키·개인정보 스캔(허용 목록: `tools/ci/allowlist.json`).

## M7. CSS로 초대 게이트를 숨겨 "왜 안 되는지"가 사라짐

- **증상**: 초대 오류 화면이 안 뜨고 앱만 열린다. 버튼을 눌러도 반응이 없다(해시만 바뀌고 재로드 없음).
- **규칙**: 게이트는 `hidden` 속성으로만 제어하고 CSS `display:none`으로 덮지 않는다. 실패 사유는 `#gateError`에 **항상** 쓴다. 참여는 `location.replace('#invite=')`만으로 처리하지 않는다(이미 `/viago/`면 재로드가 없다).
- **자동**: CI R4.

## M8. 터치 타겟이 24px 이하

- **증상**: 카드 오른쪽 `›`, 여행 변경, `+`(공유), 지도 닫기 `×`를 눌러도 잘 안 눌린다.
- **규칙**: 손가락 조작 요소는 **최소 44×44px**의 누를 수 있는 영역을 확보한다(보이는 크기는 작아도 `::after`로 히트 영역을 넓힌다). 지도 핀은 지도 조작 요소라 예외.
- **자동**: CI e2e 스모크(390×844에서 44px 미만 목록 검사).

## M9. 모바일에서 글자가 잘리거나 버튼이 겹침

- **증상**: 390px 폭에서 제목·메모가 잘리고, 지도 범례가 안내 문구를 덮는다.
- **규칙**: 한 줄 말줄임은 `min-width:0` + `overflow:hidden` + `text-overflow:ellipsis` 3종을 함께. 겹침이 생기면 `z-index`로 덮지 말고 **자리(bottom/left)를 나눈다**. 390×844에서 스크린샷으로 확인.
- **자동**: CI e2e 스모크(가로 넘침·겹침 검사).

## M10. 반지 앱(`Ring_R9`)·라이브 여행 데이터를 건드림

- **증상**: 결혼 반지 저축 앱 데이터가 바뀌거나 사라진다.
- **규칙**: `weddingRingRooms`(반지 앱) 경로는 **읽지도 쓰지도 않는다**. VIAGO는 `viagoRooms`/`viagoInvites`만 사용. 라이브 Firestore 데이터·보안 규칙은 재원 님 확인 없이 게시·수정 금지. 테스트는 에뮬레이터(`demo-viago`)에서만.
- **자동**: CI R10(클라이언트가 반지 앱 경로를 쓰지 않는지) + 스캔(프로젝트 ID/문서 덤프 커밋 금지).

## M11. Google Maps API 자동 호출로 일일 500 한도 소모

- **증상**: 화면만 열어도 Places 호출이 나가 한도가 줄어든다.
- **규칙**: 이동시간·거리는 **저장된 좌표 계산**으로만 낸다. 검색·상세는 사용자가 입력·선택했을 때만 부른다. 테스트는 Google 요청을 차단하고 OSM 타일 또는 mock을 쓴다(지도 초기화 1건 외 서비스 호출 0건).
- **자동**: CI e2e 스모크가 `maps.googleapis.com` 요청 수를 세고, Places/Geocoding 경로가 있으면 실패.

## M12. 동시 편집이 한쪽 내용을 지움

- **증상**: 두 사람이 같이 고치면 한쪽 일정이 사라진다(2026-11-14 21초 창).
- **규칙**: 저장 전 `revision`/`updateTime`을 확인하고, 충돌이면 덮어쓰지 말고 "충돌 · 선택 대기"로 멈춘다. `onlySharedFields`(payload·revision·updatedAt·updatedBy) 밖의 필드는 쓰지 않는다.
- **자동**: 규칙 에뮬레이터 테스트(`viago-emulator/`) + CI R11.

## M13. 손으로 고친 파일이 문법 오류로 앱 전체를 멈춤

- **규칙**: 큰 HTML/JS를 문자열 치환으로 고친 뒤에는 **반드시** `node tools/ci/run.mjs`. 화면이 흰색이면 먼저 콘솔 오류를 본다.
- **자동**: CI 문법 검사(인라인 스크립트 포함).

## M14. SW·페이지 빌드가 아직 `building`인데 완료로 보고

- **증상**: 배포 직후 라이브가 옛 파일.
- **규칙**: push 후 ① GitHub Actions 초록 ② Pages `built` ③ 라이브 `sha256`가 로컬과 일치 ④ `?v=`·SW `VERSION` 라이브 값 확인 **4개가 모두** 맞을 때만 "배포 완료".
- **자동**: 배포 후 `node tools/ci/verify-live.mjs <tag>`(수동 실행) + CI는 저장소 상태만 검사.

## M15. 옛 코드·옛 문서가 이어붙어 두 번 실행됨

- **증상**: 같은 이벤트가 두 번 처리되거나, 삭제한 코드가 남아 동작한다(2026-11-15 SW 병합 덮어쓰기).
- **규칙**: 자동 생성물은 생성 스크립트로만 만든다. 패치 스크립트를 적용한 뒤에는 **diff를 눈으로 확인**하고, 같은 함수 정의가 두 번 있는지 grep한다.
- **자동**: CI R12(중복 함수 정의 검사).

## M16. 기기·브라우저마다 다른 익명 계정 — "초대가 소모됐다"는 오판

- **증상**: 홈 화면 앱에서 갑자기 초대 화면. 초대는 멀쩡하다.
- **규칙**: Safari·홈 화면 앱·재설치는 각각 다른 익명 계정이다. 참여 실패를 "초대 소모"로 단정하지 말고, 서버에서 `viagoInvites/{token}`의 `usedBy`·`expiresAt`을 확인한다. 링크는 기간제 다회용(`multiUse: true`)을 기본으로.
- **자동**: 규칙 에뮬레이터(다회용 참여 3대·1회용 호환) 테스트.

## M17. 플랜 B·전날 브리핑이 기존 일정을 건드리거나 외부 API를 부름

- **증상**: 새 기능을 넣은 뒤 기존 여행(rev 160) 문서가 바뀌거나, 브리핑을 열 때마다 Places 호출이 나가 한도가 줄어든다.
- **규칙**: ① 플랜 B 는 장소 문서의 **선택 필드 `planB`(문자열)** 로만 저장한다 — 부팅·마이그레이션에서 기본값을 심지 않고, 비우면 키를 지운다(빈 값 저장 금지). ② 카드 배지는 값이 있을 때만 그리고, 펼침은 카드 안에서만(카드 탭=지도 미리보기를 가로채지 않는다). ③ 전날 브리핑은 **저장된 좌표·메모 계산으로만** 만든다(fetch·Places·Geocoding 호출 없음). ④ 진입 버튼은 상단 바의 44px 버튼, 시트는 지도 44%·타임라인 공간을 차지하지 않는다. ⑤ 라이브 문서 쓰기는 기존 `payload` 동기화 경로 그대로 — 별도 마이그레이션 금지.
- **자동**: CI R13·R14 + `tests/e2e/planb-brief.mjs`(390×844·오프라인·동기화 병합·Google 호출 0건).

## M18. 일정 행 번호와 지도 핀이 어긋남 (시안 1 번호)

- **증상**: 목록은 1·2·3 순서인데 지도 핀은 2·3·4처럼 한 칸씩 밀린다.
- **원인**: 목록 번호를 CSS `counter(journey-stop)`로 매겼다. 지도 핀 번호(`overviewEntries`의 `label`)는 **장소 배열 index+1**이고, 하루 미리보기 지도는 `항공` 장소를 그리지 않는다 — 그래서 하루에 항공편이 하나라도 있으면 카운터와 핀이 어긋났다.
- **규칙**: 목록 번호는 마크업에서 `placeNumberTag(p,i)`로 **핀과 같은 index+1**을 찍는다. 핀이 없는 행(`항공`·좌표 미확인)은 `data-pin="0"`으로 흐린 숫자를 쓴다. CSS 카운터로 번호를 만들지 않는다.
- **자동**: `tests/e2e/smoke.mjs` S4(카테고리)·S5(지도 44%) + 검증 스크립트의 번호↔핀 대조(`tmp-uiwork/number-check.mjs` 형태).

## 배포 절차 8단계 (모두 확인해야 "완료")

1. `node tools/ci/run.mjs` 통과 (문법·껍데기·비밀키·불변식).
2. 로컬 브라우저 검사: 390×844 · 1280×900에서 일정·이동 pill·인라인 미리보기·지도 카메라 유지 + `node tests/e2e/planb-brief.mjs`(플랜 B·전날 브리핑).
3. 오프라인 검사: 온라인 1회 → `setOffline(true)` 재실행에서 일정·예약 메모가 그대로, 안내 문구 표시.
4. SW `VERSION`과 `index.html`의 `?v=`를 함께 올리고 `node tools/ci/stamp.mjs`로 지문 갱신.
5. `git push origin main`.
6. GitHub Actions `VIAGO CI` 초록 확인(`gh run list -R oyeswon-gif/viago`).
7. GitHub Pages `built` + 라이브 sha256 일치 확인(`node tools/ci/verify-live.mjs`).
